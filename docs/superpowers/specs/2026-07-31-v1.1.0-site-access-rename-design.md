# Diseño: v1.1.0 — Acceso a sitios + renombrado Gemini Notebook

**Fecha:** 2026-07-31  
**Rama:** `version/1.1.0`  
**Base:** `main` (v1.0.0)  
**Estado:** pendiente de revisión del usuario antes del plan de implementación.

## Objetivo

Publicar una versión **menor (1.1.0)** que:

1. Funcione en el host actual del producto (`https://notebook.google.com/`) y siga soportando `https://notebooklm.google.com/` cuando el usuario lo conceda.
2. Permita **configurar el acceso a sitios** desde el popup (activar/desactivar presets y añadir/quitar patrones personalizados).
3. Renombre la extensión de forma visible a **Filtro de Estudio para Gemini Notebook** (NotebookLM = nombre anterior).

Mantener la extensión **ligera**: sin bundler, sin dependencias nuevas en runtime.

## Contexto

Google renombró NotebookLM a Gemini Notebook. Las sesiones autenticadas pueden resolver a `notebook.google.com` o a `notebooklm.google.com` según la cuenta. La v1.0.0 solo declara `https://notebooklm.google.com/*` en `host_permissions` y `content_scripts`, por lo que no se inyecta en el host nuevo. Edge muestra esos hosts en “Acceso a sitios”; deben poder gestionarse también desde la extensión.

## Decisiones de producto (validadas)

| Tema | Decisión |
|------|----------|
| Enfoque | Manifest estático para los dos hosts de notebook + registro dinámico para extras |
| Hosts | Los tres presets son **opcionales** (`optional_host_permissions`), no `host_permissions` fijos |
| UI | Presets + campo para añadir/quitar patrones arbitrarios |
| Primer uso | Al primer open del popup, pedir automáticamente los tres presets |
| Renombrado | Nombre/descripción/UI/docs → Gemini Notebook; **no** renombrar el repo GitHub |
| Versión | `1.1.0` en rama `version/1.1.0` |

## Arquitectura

### Manifest

- `version`: `1.1.0`
- `name`: `Filtro de Estudio para Gemini Notebook`
- `description`: texto actualizado (Gemini Notebook; filtrar tipos/fuentes en Studio)
- Eliminar `host_permissions` requeridos.
- Añadir `optional_host_permissions`:
  - `https://notebook.google.com/*`
  - `https://notebooklm.google.com/*`
  - `https://accounts.google.com/*`
- Añadir permiso `scripting` (registro de content scripts para hosts custom).
- `content_scripts` y `web_accessible_resources.matches`: ambos hosts de notebook.
- Permisos existentes sin cambio de semántica: `storage`, `activeTab`.

### Detección de host

- Un único helper compartido conceptualmente (en `content.js` y `popup.js`, o módulo mínimo si ya hay patrón): `isNotebookHost(hostname)` / `isNotebookUrl(url)` acepta `notebook.google.com` y `notebooklm.google.com`.
- Sustituir `PAGE_HOST = 'notebooklm.google.com'` y `tab.url.includes('notebooklm.google.com')`.
- El `notebookId` sigue extrayéndose del UUID del path (sin cambio de regex).

### Popup — Acceso a sitios

- Sección nueva “Acceso a sitios” (además de chips de tipo/fuente).
- Toggles para los tres presets: concedido ↔ `chrome.permissions.request` / `remove`.
- Lista de hosts personalizados + quitar (revoke + unregister).
- Campo + “Añadir”: normalizar a origen `https://host/*` (rechazar `http:`, wildcards inválidos, orígenes vacíos); luego `request` + registrar scripts.
- Flag `siteAccessPrompted` en `chrome.storage.local`: si ausente, en el primer `DOMContentLoaded` del popup se llama a `permissions.request` con los tres presets y se marca el flag (también si el usuario cancela el diálogo, para no re-preguntar en bucle). Los toggles permiten reintentar después.
- Si no hay ningún host de notebook concedido: mensaje claro; no intentar aplicar filtros a pestañas no válidas.

### Background (service worker)

- Al arrancar y en `chrome.permissions.onAdded` / `onRemoved`: sincronizar content scripts registrados para hosts **custom** (no los dos del manifest).
- Registro: mismos bundles que el manifest (MAIN: `filter-core.js` + `page-bridge.js`; ISOLATED: `filter-core.js` + `content.js`), `run_at: document_start`.
- Persistencia de la lista de patrones custom en `chrome.storage.local` (p. ej. `customHostPatterns: string[]`), filtrada a los que aún tienen permiso concedido.

### Renombrado (visible)

- Manifest name/description.
- Textos de UI/popup/status que digan “NotebookLM” como nombre de producto → “Gemini Notebook”.
- README y CONTRIBUTING: título y enlaces al producto; una línea que NotebookLM es el nombre anterior.
- **Fuera de alcance:** renombrar el repositorio `NotebookLM-Study-Filters`.

## Flujo de datos

```
Popup (primer open) → permissions.request(presets) → storage.siteAccessPrompted=true
Popup toggle/add/remove → permissions.request|remove → (custom) background register|unregister
Pestaña notebook con permiso → content_scripts (manifest o registered) → panel filtros (igual que 1.0.0)
```

## Manejo de errores

- Diálogo de permiso denegado: UI “acceso denegado”; sin crash; reintento vía toggles.
- Patrón inválido: mensaje breve; no llamar a la API.
- Se mantiene el blindaje “Extension context invalidated” y el fallback inline de `FILTER_CORE`.
- Sin host de notebook: popup informa; no envía apply a pestañas ajenas.

## Criterios de aceptación

1. Con permiso en `notebook.google.com`, el panel aparece en Studio.
2. Con permiso en `notebooklm.google.com`, sigue funcionando.
3. El popup permite activar/desactivar presets y añadir/quitar hosts custom.
4. El primer open del popup solicita los tres presets.
5. Nombre visible: “Filtro de Estudio para Gemini Notebook”.
6. Versión `1.1.0`; `npm test` en verde.

## Fuera de alcance (YAGNI)

- Renombrar el repositorio de GitHub.
- Bundler o dependencias runtime nuevas.
- UI avanzada de permisos más allá de presets + lista/añadir/quitar.
- Soporte por defecto a `notebooklm.cloud.google.com` (el usuario puede añadirlo como custom).
