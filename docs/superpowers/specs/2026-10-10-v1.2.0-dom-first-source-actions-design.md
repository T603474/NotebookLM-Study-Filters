# Diseño: v1.2.0 — Filtros DOM-first, nombres de fuente y acciones por fuente

**Fecha:** 2026-10-10  
**Rama:** `claude/notebooklm-filters-improvements-aca780`  
**Base:** `main` (v1.1.0)  
**Estado:** pendiente de revisión del usuario antes del plan de implementación.

## Objetivo

Publicar una versión **menor (1.2.0)** que:

1. **Mantenga el panel sincronizado con lo que existe.** Al borrar un elemento de estudio, chips, contadores, "Mostrando N de M" y filtros guardados se corrigen solos.
2. **Muestre el nombre real de cada fuente** en lugar de `Fuente 0e58e2c4`.
3. **Permita actuar sobre las fuentes seleccionadas:** marcarlas en el chat y borrar los elementos de estudio visibles.

Mantener la extensión **ligera**: sin bundler, sin dependencias nuevas en runtime.

## Fuera de alcance

- Borrar las propias fuentes del notebook (decisión del usuario).
- Acciones mediante RPC no oficiales de `batchexecute`.
- Acciones en el popup (el popup sigue solo filtrando).
- Eliminar el duplicado `INLINE_FILTER_CORE` de `content.js` (deuda conocida; se mitiga con un test de paridad, ver Pruebas).

## Decisiones de producto (validadas)

| Tema | Decisión |
|------|----------|
| Enfoque de base | **DOM-first**: el DOM actual decide qué existe; la red solo aporta metadatos |
| Identidad de fuente | Por **UUID** (`ID:<uuid>`), no por clave de tema |
| Acciones sobre fuentes | **Borrar elementos de estudio** visibles y **marcar fuentes en el chat**; no borrar fuentes |
| Vía de ejecución de acciones | **UI nativa** de Gemini Notebook (menú ⋮ y diálogo nativos), no RPC |
| Alcance de "Borrar" | Lo que se ve tras filtrar (WYSIWYG), con confirmación previa |
| Entrega | Un spec, tres hitos con plan propio: (1) #1, (2) #2, (3) #3 |
| Versión | `1.2.0` |

## Arquitectura

### Modelo (lógica pura en `filter-core.js`)

```
Artifact { id, kind, title, sourceIds[] }       // solo los presentes en el DOM
Source   { id, name, nameKnown, key }           // key = clave de tema (T047), opcional
Model    { artifacts[], sources[],
           counts: { byKind, bySourceId, total } }
```

`buildStudyModel(domItems, networkDict)` recibe los elementos leídos del DOM (`id`, `title`, `details`, `kind`) y el diccionario de red (`artifactId → {kind, sourceIds, title}`, `sourceId → título`). Devuelve el `Model`. Una fuente aparece solo si algún artefacto presente en el DOM la referencia. No toca el DOM ni `chrome.*`.

### Reconciliación (`content.js`)

- Cada pasada (`runOnce`) lee los `artifact-library-item` presentes, llama a `buildStudyModel` y renderiza chips, contadores, "Mostrando N de M" y estado vacío **desde el modelo**. Se elimina la caché de claves de chips (H1).
- `applyFilters` deja de salir pronto con 0 elementos (H5).
- El diccionario de red (`artifactMetaCache`, `sourceTitleById`) sigue siendo append-only: es un diccionario, no la fuente de verdad de la existencia (H2).

### Enlace DOM↔metadatos

- El id se **revalida en cada pasada**: si `dataset.nlArtifactId` ya no está en el diccionario o el título del DOM no coincide con el de los metadatos, se descarta y se vuelve a resolver (H4).
- Orden de resolución: atributos con UUID del propio elemento → coincidencia única por título → **fallback posicional**, que solo se acepta si el título del candidato coincide con `getTitle(item)`.
- Un elemento sin enlace se clasifica por señales del DOM (detalles, icono), cuenta como "sin fuente conocida" y **queda excluido de las acciones**.
- Un artefacto renombrado en la UI no coincide por título y degrada al caso anterior. Si el spike S2 demuestra que el DOM expone el id del artefacto, el fallback posicional se elimina.

### Chips de fuente y filtros guardados

- Un chip por fuente (`src = ID:<uuid>`, reutiliza `SOURCE_ID_PREFIX` y la lógica existente de `matchesSourceQuery`). El buscador de fuentes mantiene su semántica actual (clave de tema o nombre).
- **Migración al cargar:** una clave guardada `Tnnn` se traduce a los `ID:<uuid>` del modelo cuyo `key` coincide; si no coincide ninguna, se descarta. Se persiste el mapa traducido.
- **Poda de huérfanos:** tras cada reconciliación, las fuentes seleccionadas que ya no están en el modelo se eliminan del filtro guardado (H3). Migración y poda **solo se ejecutan si el modelo tiene al menos un artefacto**, para no borrar la selección del usuario mientras el DOM aún carga. Si se borran todos los elementos no hay nada que ocultar, así que no hay filtro fantasma.

### Renderizado seguro

El panel se construye con nodos DOM (`createElement`, `textContent`, atributos), no con `innerHTML` concatenado (H8). Si el conjunto de chips no cambia, solo se actualizan los textos de contador y `aria-pressed` en sitio, sin reconstruir (conserva foco y texto de los buscadores y no realimenta al `MutationObserver`).

## Nombres de fuente (#2)

Orden de obtención del título de una fuente:

1. Título de la respuesta de red (`parseNotebookBatchResponse`).
2. Panel Fuentes nativo, con selectores **validados contra el DOM real** (sustituyen a los genéricos de `scanSourcesPanel`); se asocian por UUID si el DOM lo expone, o por título/clave única si no.
3. Fallback visible `Fuente sin nombre · <4 caracteres del uuid>`.

**Spike S1 (solo lectura, ejecutado por el usuario).** Se amplía `snippets/nl-debug.js` para volcar: los `rpcids` de `batchexecute` capturados, la forma (profundidad y tipos, sin contenido) de las filas candidatas a fuente, y la estructura del DOM del panel Fuentes. El usuario lo ejecuta en la consola de DevTools y pega la salida; puede enmascarar títulos. No se requiere acceso del asistente a su sesión. El resultado fija el mecanismo 1 o 2 del orden anterior; mientras tanto el hito 2 no empieza.

## Acciones por fuente (#3)

Solo en el panel in-page. Fila de acciones con dos botones, deshabilitados si n=0 o hay una acción en curso. Máquina de estados: `idle → confirming → running → done | failed | cancelled → idle`.

### Marcar en chat (n = fuentes seleccionadas)

Deja marcadas en el panel Fuentes nativo **exactamente** las fuentes seleccionadas y desmarca el resto. Si el panel no está montado o no localiza una fuente, se informa y no se adivina ni se modifica nada.

### Borrar visibles (n = elementos visibles con id resoluble)

- **Confirmación:** modal propio, construido con nodos DOM, con el recuento y los títulos (máximo 10 y "y M más"), aviso de irreversibilidad y foco inicial en **Cancelar**. Los elementos sin id resoluble se excluyen y se informa de cuántos.
- **Ejecución secuencial.** Por elemento: volver a localizarlo por id, abrir su menú ⋮, pulsar la entrada de eliminar (coincidencia por texto/`aria-label` ES/EN, p. ej. `eliminar|borrar|delete|remove`, validada por S2), confirmar el diálogo nativo y esperar a que salga del DOM. Timeouts como constantes con nombre (menú ≤ 2 s, diálogo ≤ 2 s, salida del DOM ≤ 8 s).
- **Control:** el botón Cancelar se consulta entre elementos. Se **para al primer fallo** con un informe "Borrados k de N; falló «título»". Si el diálogo nativo no coincide con lo esperado, se aborta sin pulsar nada.
- **Después:** la reconciliación del modelo refresca chips, contadores y filtros (mismo mecanismo que #1). Se aborta si `extensionContextLost`.

**Spike S2 (solo lectura, ejecutado por el usuario).** Mismo snippet ampliado: volcado de la estructura del menú ⋮ de un elemento, del diálogo de confirmación, de las casillas del panel Fuentes y de los atributos que contienen un UUID en un `artifact-library-item` (para saber si el DOM expone el id del artefacto). El hito 3 no empieza sin S2; el hito 1 no depende de S1 ni de S2.

## Gestión de errores

- Contexto de extensión invalidado: se mantiene el `teardown` actual.
- Acciones: cualquier selector no encontrado detiene la acción y se informa en el propio panel; nunca se hace clic "a ciegas".
- Los fallos del panel Fuentes nativo no afectan al filtrado.

## Pruebas

- **`filter-core.test.js`:** `buildStudyModel` (desaparición de fuente y recuentos al quitar un artefacto, fuente sin título, elementos sin enlace), migración de claves `Tnnn`, poda de huérfanos con modelo vacío y no vacío.
- **`content.dom.test.js` (jsdom):**
  - Quitar un `artifact-library-item` del DOM refresca chips, contadores y "Mostrando".
  - Una fuente seleccionada cuyo último elemento se borra deja de filtrar.
  - Nombre de fuente con HTML (`<img src=x onerror=…>`) se muestra como texto.
  - Flujo de borrado contra un menú simulado: éxito, fallo a mitad, cancelación.
  - Flujo de marcado de fuentes contra un panel simulado.
- **Paridad:** un test ejecuta el `filter-core.js` y el `INLINE_FILTER_CORE` con el mismo fixture y exige resultados idénticos (evita que el duplicado diverja).

## Riesgos y dependencias

- **Dependencia de la UI de Google.** Menú ⋮, diálogo de confirmación y panel Fuentes pueden cambiar sin aviso; por eso las acciones fallan de forma segura (informan y paran) y los selectores se concentran en un único módulo fácil de actualizar.
- **Borrado irreversible.** Mitigado con confirmación propia, parada al primer fallo y exclusión de elementos sin id resoluble.
- **Origen de los títulos de fuente desconocido hasta S1.** Si ni la red ni el DOM los exponen, el fallback visible `Fuente sin nombre · xxxx` se mantiene y se documenta como limitación.
